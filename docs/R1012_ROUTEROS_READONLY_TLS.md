# R10.12 — Narrow RouterOS REST HTTPS first read, not physical adoption

PRD FR-019 and AC-05 require physical MikroTik read interoperability before compatibility may be claimed. R10.07–R10.09 already provide tenant-aware non-executable PPPoE dry-run and distinct Provisioning Officer and Security Admin approval. R10.12 adds a native Rust first-read transport targeted ONLY to the initial owner-reported DEV-08 RB951Ui-2HnD / mipsbe / RouterOS 7.23.7 tuple. RouterOS REST on HTTPS port 443 is NOT the binary RouterOS API-SSL protocol on 8729.

The adapter sends only one fixed GET /rest/system/resource, accepts no arbitrary CLI path, URL or write method, refuses non-RFC1918/loopback and non-443 destinations, rejects redirects and non-JSON replies, and never falls back to insecure HTTP. A locally supplied independently approved DER CA must verify the exact management IP SAN through rustls and an independent SHA-256 leaf fingerprint must also match. Nonroot CLI reads credentials and CA only from absolute, private 0600 regular files outside a group-readable directory. No credentials, raw resource JSON or serials are printed or placed in a repository. Bound per-operation TLS/network timeouts are five seconds; total HTTP wire data is limited to 64KiB, with JSON body maximum 32KiB. It currently deliberately rejects chunked transfer encoding until a physical response shape can be recorded and parser tests explicitly cover it.

The existing strict R6.2 normalizer compares only the exact expected hardware/RouterOS version and returns UNREVIEWED inventory. It never promotes physical adoption, tenant binding or PPPoE writes. A successful synthetic unit test is NOT vendor interoperability.

After separate actual management-route/OOB cert approval, a nonroot operator can run a locally built routeros-secure-read Rust CLI with ONLY these externally supplied variables: IPAT_R1012_READ_ONLY_APPROVED=YES, IPAT_R1012_PRIVATE_TARGET=APPROVED_PRIVATE_IPV4, IPAT_R1012_CREDENTIAL_FILE=ABSOLUTE_PRIVATE_0600_FILE, IPAT_R1012_APPROVED_CA_DER_FILE=ABSOLUTE_PRIVATE_DER_0600_FILE, IPAT_R1012_APPROVED_LEAF_SHA256=REVIEWED_64_LOWERCASE_HEX. Do not put a device password/secret/cert private key in the repository or prompt. CLI denies nonroot violations, missing local certificate material and unapproved targets before any network request.

Tests assert strict request method, target/network filtering, bounded HTTP framing, non-secret normalization, credential parsing and rejection. Physical RouterOS profile, TLS CA/leaf fingerprint, actual PPPoE read, independent review and production tenant/device binding remain UNVERIFIED until real evidence is collected.
