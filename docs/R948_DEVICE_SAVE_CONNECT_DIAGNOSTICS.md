# R9.48 — Device Save → Connect → Verify (lab first implementation)

Owner-reported defect: R9.47 required a hidden One-Time Owner Code before even saving and returned the generic "Check supported device profile and required fields". The dashboard failed to show a real saved device row. This is a faulty state transition, NOT evidence that SSH authentication or the network failed. A separate owner-VPS direct TCP probe independently reached the current ZTE C320 laboratory management SSH port during investigation; that does not establish credentials, actual firmware identity or successful authenticated CLI.

## User-facing contract

1. **Save Device** first validates the typed target against the backend's existing one-device allowlist, then writes only nonsecret metadata to a mode0600 private owner-VPS `device-draft.json`. A saved record becomes visible in the **real device row** in Device List immediately as **Pending · Owner Verification**; it must survive page refresh and connector restart. It is never merged with synthetic candidates, and saved/draft is NOT "Adopted".
2. **Connect** immediately runs a bounded, fixed-target three-second TCP diagnosis from the actual VPS. `TCP_REACHABLE_AUTH_NOT_TESTED` means the SSH port accepted TCP but login was **not** tested. `SSH_PORT_REFUSED` identifies a listener refusal; `NETWORK_UNREACHABLE` a local route/host failure; `TCP_TIMEOUT_NETWORK_OR_PORT` must not falsely distinguish a remote firewall from a missing route. No arbitrary browser IP/port probe or freeform CLI.
3. For this **temporary private lab** only, if a device password was entered but the owner-verification code is missing, leave the password in its existing password input, expand **Advanced Security** automatically, focus the missing field and explain **"Device Saved · Pending Owner Verification"**. Never send it to the device, persistent server storage or browser local/session storage before owner verification. Do not block or discard nonsecret Save. Genuine tenant-scoped authenticated administrative sessions should replace this code in a subsequent milestone; do not silently remove the current ownership control while preview :3002 is not production authenticated.
4. When complete, the server passes only the fixed vendor read commands through the pinned SSH adapter. The connector returns bounded, nonsecret stages `OWNER_VERIFICATION_FAILED`, `SSH_HANDSHAKE_OR_AUTH_METHOD`, `SSH_AUTH_FAILED_OR_UNKNOWN_PROMPT`, `DEVICE_CLI_RESPONSE_UNSUPPORTED` or a generic fail-closed stage. A login error must NOT be called a wrong password with certainty if the prompt or authentication method is also unsupported. Credentials are encrypted on VPS **only after actual validated physical card output**. The saved draft remains visible on all failure paths. No physical configuration writes are authorized.
5. Success changes state to `READ_ONLY_CONNECTED_LAB` with source timestamp, then persistent bounded read refreshes can run without repeated Terminal login. Green remains strictly gated on fresh authenticated device data. The historical 72 manually observed ONU IDs are not current per-ONU health measurements.

**Scope limit:** R9.48 actually supports the previously pinned physical ZTE C320 lab management profile only. It does NOT make arbitrary IPs, C-DATA, VSOL, MikroTik, vendor firmware upgrades, tenant RBAC or WireGuard/IPsec self-service functional. The current private preview is NOT commercial SaaS Device Manager. Durable PostgreSQL per-tenant inventory and a production per-device queue are follow-up MUST work; the immediate pending metadata file is an isolated lab bridge, not a substitute.

**Acceptance tests:** JS submit simulation proving draft is saved before missing-code validation and only one SSH-auth attempt after full input; 5 nonsecret Python connector tests; locked offline Rust workspace; actual private HTTP POST draft and re-read status; bounded fixed TCP probe; hardware write POST 403; original :3000 service healthy. Deployment status is recorded separately in PROJECT_STATUS.md; a source change alone does not prove runtime installation.
