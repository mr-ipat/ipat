# R9.62 — Device master data and Platform Admin domain staging

## Actual operator changes

**Device Manager:** `http://127.0.0.1:3002/lab/device-workbench#managed-devices` through existing owner Mac SSH tunnel. A formerly free-text POP/Site field is now a required selector populated from `GET /lab/owner/pops`. When no POP is registered, the UI proposes **Create POP/Site**, submits code+display name to a durable, strict server-side POP master and resumes Add Device. POPs can be renamed, listed and removed only if unassigned; backend checks both saved devices and linked physical C320. Existing C320 POP assignment is metadata only and never edits protected management credentials. The free-text Vendor field is now a selector populated from `GET /lab/owner/device-catalog`, filtered by device type and candidate management protocol. ZTE C320's two live read commands are the ONLY currently evidenced physical pilot. ZTE/C-DATA/VSOL/MikroTik other combinations are clearly labelled **inventory candidates**, not supported hardware operations, and Save does not pretend they connect.

**Platform admin domain control:** `http://127.0.0.1:3002/lab/platform-admin/domains`. The owner can store a private operator *draft* of desired main hostname and temporary public IP, and planned managed tenant subdomains or custom customer domains. The backend returns read-only preview A/TXT *names* and always shows **Not routed / DNS unverified / HTTPS not ready**; no TXT challenge value is issued before actual tenant ownership verification. Changes do not reconfigure DNS, TLS, edge binding or firewall, and cannot grant tenant roles. A main-hostname change is blocked when planned managed subdomains would require explicit review. The existing `ipat.fadly.id` is currently the SSH lab management host and must NOT be repointed.

## PRD BLOCKER: public and tenant production deployment

A publicly resolvable DNS A-record and a planned IP **do not make a secure operational dashboard**. 2026-10-02 external read-only check found `ipat.fadly.id` A `202.162.204.121`, but HTTPS connection to port 443 failed. The actual private app binds `127.0.0.1:3002`; the deployment owner account has no noninteractive root privileges, and trusted provider-console rescue/complete backup/TLS and production IdP/tenant PostgreSQL runtime gates are not yet closed. Do not expose :3002 to the Internet or redirect the SSH lab hostname to improvise a commercial domain. Complete independently secured provider-console owner recovery and authorized production deployment, HTTPS ingress, verified domain ownership and proper platform/tenant authentication before activating `ipat.id`, managed tenant subdomains or tenant custom domains. No custom domain shall become Active merely because an operator saves it in the staging UI.
