## Immediate fix to the confusing screenshot

The old lab onboarding used cramped cards, unnatural mixed technical translations, a hardwired device label and a second prominent owner code. R9.47 places a clean **Add Device** form in the operator console with responsive aligned labels: **Device Name**, **Device Type** (OLT/ONT/Router/Other), **Vendor / Model**, **Management Protocol**, **Management IP**, **SSH Port**, **Username**, **Password** and a **Connect & Save** action. One-time owner verification remains inside collapsed **Advanced Security** while the private lab has no production admin auth. Browser-side options depend on Device Type; UI shows future C-DATA, VSOL, ZTE ONT and MikroTik options as **Coming Soon** and does NOT falsely mark them connected. The field values for the one physically known C320 target are prefilled so the owner need not retype them.

For this release the C320 model is bound to the ONE actual previously observed pinned SSH management endpoint and account, and Rust's backend independently rejects unsupported type/address/port/username even if the browser is modified. Arbitrary IP/port/username/vendor onboarding is **NOT** implemented: it will require tenant identity, scoped per-tenant target allowlists, independently verified host keys/CA and vendor-specific connector mapping. Do not pretend a cosmetic free-text IP field authorizes arbitrary SSH or SSRF. The owner code is still a necessary **temporary LAB-only** private verification; remove it only when genuine administrator login/OIDC+MFA and server-side tenant enforcement replace it, not by exposing privileged device credentials to anonymous browser users.

Current C320 connection path after form submission: typed and bounded private JSON -> Rust fixed-target validation -> existing mode0600 Unix connector -> device pinned SSH/card proof -> encrypted stored credential; only then show `READ_ONLY_CONNECTED_LAB` with last verified time and change the status badge green. User-entered Device Name is presently only UI-labeled/validated (and **not yet persisted** to durable device inventory), because an authenticated tenant-owned device registry has not been deployed. In this restricted lab the physical device has canonical ID DEV-01 and model ZTE C320; do not claim a generic device record was added. After enrollment the server's persistent read worker eliminates re-entering credentials for every button.
